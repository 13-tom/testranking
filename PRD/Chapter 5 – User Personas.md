# Chapter 5 – User Personas

**Project:** Board Ranking

**Document Type:** Product Requirement Document (PRD)

**Version:** 1.0

---

# 1. Introduction

Every successful product is built for specific users.

Board Ranking is designed around real students and their learning journey.

Instead of building features first, we first understand who will use the platform and what problems they face.

This chapter defines the primary and future users of Board Ranking.

---

# 2. Primary User – Student (MVP)

The student is the most important user of the platform.

Every product decision should prioritize the student experience.

## Student Goals

A student wants to:

* Practice regularly.
* Improve marks.
* Understand weak chapters.
* Track progress.
* Compare performance.
* Prepare confidently for examinations.

The student does not care about complex software.

The student only wants a simple platform that helps improve academically.

---

## Student Problems

Students often experience:

* Not knowing where they are weak.
* Inconsistent practice.
* No meaningful feedback.
* Difficulty tracking improvement.
* Low motivation.
* No clear study direction.

Board Ranking solves these problems through structured testing and analytics.

# 3. Secondary User – Admin (MVP)

The Admin manages the entire platform.

Students never interact directly with administrative features.

---

## Admin Responsibilities

Manage Students

Manage Questions

Create Tests

Publish Tests

Manage Reports

Manage Subscriptions

Review Reported Questions

Archive Questions

System Settings

Analytics

---

## Admin Goals

Maintain high-quality content.

Ensure fair rankings.

Review student reports.

Manage platform growth.

Protect question quality.

---

## Admin Permissions

Admins have full platform access.

Examples:

Create Question

Edit Question

Bulk Upload Questions

Archive Questions

Create Tests

View Reports

Manage Students

Manage Payments

Manage System Settings

---

## Admin Responsibilities

Admins are responsible for maintaining the quality of the Question Bank.

Questions are never published without admin approval.

The Question Bank is considered one of the company's most valuable assets.

# 8. Product Design Rules

Whenever a new feature is proposed, ask:

Which user is this built for?

If the answer is unclear,

the feature should not be developed.

Every screen should have one primary user.

Examples:

Landing Page

Student

Dashboard

Student

Question Bank

Admin

Reports

Admin

Analytics

Student

---

# 9. Product Responsibility

Board Ranking is responsible for providing:

* Reliable Questions
* Accurate Evaluation
* Fair Rankings
* Meaningful Analytics
* Secure Student Data

Students are responsible for:

* Honest Test Attempts
* Following Community Guidelines
* Protecting Account Credentials
